APPROVE
Built review rounds. `POST /api/tasks/{id}/rounds` and `POST /api/projects/{id}/tasks` with `submit` go through one helper, `insert_round`. It checks the 5 MB limit first (413), then for an empty patch (422), then splits the patch with `split_patch`, works out `n` and the trigger, and writes the round and its `round_files` rows inside the caller's `BEGIN IMMEDIATE`. On a standalone task, every round sets review · human_review. On a worktree task, a round changes neither status nor stage. `GET …/rounds/{n|latest}/diff` returns the joined patch as `text/x-diff`, sent with `nosniff`. `fctl submit [<id> | --new --title T]` captures changes through a temp index with pinned diff flags, and `fctl diff <id> [--round N]` prints a round's patch. No schema change and no new dependencies.
Rounds: 2 of 2. Round 1: security asked for CHANGES. Malformed C-quoting in a name went to `codecs.escape_decode` and gave a 500. Round 2 fixed it (now 422), and also adopted security's nits: `safe_path()` rejects empty, absolute, `..`, and NUL paths with a 422, and the diff response has `nosniff`. Tests: 243 passed in round 2 (build.md, and confirmed by review-code). AC1–AC41 each map to a named test in tests/test_rounds.py or tests/test_cli.py. AC16 now has 14 bodies.
Docs: no conflicts. The capture uses the resolved `base_sha` where §7.4 writes `HEAD`, which gives the same result. Writing an `events` row only when status or stage changes matches §5.2's "every change writes an events row".
Non-blocking, beyond the spec: there is a global `UnicodeEncodeError` handler. A lone surrogate such as `\ud800` now gives a 422 on every route (it was a 500), including 003's routes. ## Open questions
- Q1 (round trigger): round 1 is `initial`. If round n−1 has a `me` CHANGES_REQUESTED decision, the round is `human`. Otherwise it is `agent`. Spec default.
- Q2 (standalone status): a task with `worktree_path` NULL is standalone. Every round on it sets review · human_review from any status, including done. It also clears `done_at`, keeps `position`, and bumps `updated_at`. An `app` event is written only if status or stage changed. A worktree task's status and stage are never touched, and nothing blocks a submit. Spec default. Builder detail: a round on a worktree task does not bump `updated_at` either.
- Q3 (submit rows): one transaction creates the task and round 1. The task is review · human_review at 1 + the highest review position (1.0 if there is none), with one `app` event from NULL to review. The response uses §7.4's keys, with `task_id`. Round 1's `build_md` is NULL. Spec default. Builder note: Q4's single model means a `submit` that includes `build_md` stores it. fctl never sends it, so the NULL holds in practice.
- Q4 (validation): one `RoundBody` model. `base_sha` must be 7–64 lowercase hex, otherwise 422. A blank patch gives 422 `no changes to submit`. A patch that doesn't start with `diff --git` gives 422. A path that can't be read gives 422. Spec default. Builder additions: the message is `can't read a safe file path in: <header, first 200 chars>`. A `+++`/`---` name without the `b/`/`a/` prefix counts as unreadable. `safe_path()` rejects empty, absolute, `..`, and NUL names, for `path` and for a rename's `old_path`.
- Q5 (5 MB): only the patch is measured, as UTF-8 bytes, and anything over 5 × 1024 × 1024 gets 413 `patch over 5 MB`. This applies to both routes and runs before the other patch checks. Spec default.
- Q6 (split): the patch is split on `\n` only, at each `diff --git ` line. The change type comes from the rename, new-file, and deleted-file lines. The path comes from `rename to`, else `+++ b/`, else `--- a/`, else the header split at its midpoint. Git's trailing tab is stripped and quoted names are C-unquoted. A `Binary files … differ` line counts +0 −0. Counts start after the first `@@`. Two sections for the same path merge into one `modified` row. Rows keep patch order. Spec default. Builder detail: a merged row's `old_path` is NULL.
- Q7 (diff route): `latest` is the highest `n`. The body is the round's patches joined in rowid order. A missing round, or a non-integer `n`, gives 404 `#<id> has no round <n>`. `latest` with no rounds gives 404 `#<id> has no rounds`. An unknown task gives a bare 404. Spec default.
- Q8 (capture): git runs in the cwd, and only the project lookup uses `main_checkout()`. The temp `GIT_INDEX_FILE` lives in a `TemporaryDirectory`. Flags: `-c core.quotePath=false diff --cached -M --no-color --no-ext-diff --no-textconv --no-relative --src-prefix=a/ --dst-prefix=b/`. Output is read as bytes and decoded as UTF-8 with `errors="replace"`. No `--binary`. Spec default. The builder passes the resolved `base_sha` to `read-tree`/`diff` instead of `HEAD`.
- Q9 (stdin): stdin is read only when it isn't a TTY. From a terminal, `""` is sent. Spec default.
- Q10 (output): `Review #<id>: N files, +A −D → <url>` for `--new`, and `Round <n> of #<id>: …` for a round. One file reads `1 file`. `−` is U+2212. `fctl diff` writes the body as is. Spec default.
- Q11 (CLI errors): exactly one of `<id>` or `--new`, and `--title` only with `--new`. Anything else is exit 2 with usage. Outside a repo, it uses the existing message. With no commit at HEAD, exit 1 with `HEAD has no commit yet; commit once before submitting`. Another failed git step gives exit 1 `git <step> failed: <stderr>`. There is no check that the task belongs to the cwd's project. Spec default.
