## Open questions
- Q1 (where content comes from): default used. Files are read from disk in the main checkout at their resolved real path, not with `git show`.
- Q2 (which paths can be viewed): default used. A path must exactly match an `ls-files -z` entry before any filesystem call. Anything else gets a 404 HTML page: `<path> is not a tracked file in <project>`. Then the `realpath` must be inside the root.
- Q3 (resolves outside the root, or isn't a regular file): default used. The page returns 200 with `Not shown: points outside the project.` or `Not shown: not a regular file.`. Symlinks to regular files inside the root are followed. Builder's note: this includes symlinks into `.git/`, so a tracked `cfg -> .git/config` displays the config even though `?path=.git/config` itself returns 404. The security reviewer marked this as allowed by §4.5 and Q3, not a defect. The optional fix is to treat a resolved path under `<root>/.git` as not viewable.
- Q4 (binary and decoding): default used. A file is binary if it has a NUL in its first 8000 bytes. Text is decoded as UTF-8 with `errors="replace"`. A name that doesn't decode is listed with U+FFFD and its link returns 404. No AC covers that name case, so it has no test. The builder checked it once by hand with `update-index --cacheinfo`.
- Q5 (what 1 MB means): default used. The limit is `1024 * 1024` bytes, checked with `os.stat` before reading. A file is over the limit at `> 1048576` bytes, and the same rule applies to README.md.
- Q6 (which README is the landing): default used. Only a tracked root `README.md`, under the Q2 to Q5 rules. Otherwise the page shows `No README.md in this project.`.
- Q7 (branch on a detached HEAD): default used. `branch --show-current`, and `detached HEAD` when it prints nothing.
- Q8 (tree shape and empty state): default used. `file_tree()` in `ls-files` order. A directory's `<details>` is open only if it holds the shown file. The shown file's link gets `aria-current="page"`. With no tracked files the page shows `No tracked files.`.
- Q9 (viewer markup and highlighting): default used. A gutter sits beside one `<pre><code>` that holds the whole file. The language is the lowercase extension, used only if `hljs.getLanguage` knows it. Lines end at `\n`, `\r\n` or a lone `\r`, and a final line ending adds no extra line. An empty file shows `Empty file.`.
- Q10 (git fails): default used. 200 page with `role="alert"`: `Can't list files in <path>: <first stderr line>` (or `git timed out`), and no tree. Builder's choice: a request with `?path=` while `ls-files` fails also gets this alert page, not a 404, because membership can't be checked.
- Builder's presentation choice (not in the spec): the README's `# Hello` renders as a second `<h1>`, under the page's `<h1>`. The landing puts a `<h2><code>README.md</code></h2>` heading above it.
