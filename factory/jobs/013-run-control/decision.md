## Open questions
- Q1 Stop vs. exit thread: the builder used the spec default. Stop sets `stopped`, `ended_at` = now, and `error` NULL before signalling, and `finish_run` then fills in only `exit_code`. Round 2 change: `finish_run` now commits `exit_code` on its own right after `proc.wait()`.
- Q2 edge cases: spec default. Not running → 409 `run #N is not running`. pid NULL → row marked, no signal. ProcessLookupError ignored. SIGTERM only. The gap between the insert and the stored pid is accepted with a `ponytail:` comment. Builder additions: unknown run → 404 `run #N not found` (was "Not Found"), PermissionError is ignored too, and no signal is sent once `exit_code` is set. So if the leader has exited, live members left in its group are not signalled (security nit, accepted).
- Q3 Stop and the task: spec default. The task's status, stage, and `updated_at` are untouched, and no event is written.
- Q4 shutdown: spec default. Each `running` run gets the same handling as Stop, without waiting for exits, so `exit_code` stays NULL after serve stops.
- Q5 startup: spec default. `failed` / `app restarted`, `ended_at` = now, `exit_code` NULL, no signal, task untouched.
- Q6 log cursor: spec default. `after`/`next` count complete `\n` lines, a trailing partial line is held back, and the whole file is read on each poll (`ponytail:` byte offsets later).
- Q7 log mapping: spec default, with two builder changes. The summary (and the Q8 name) is the first non-empty string among the keys, so an empty `command` falls through to the next key. A `parent_tool_use_id` that isn't a string gives `agent`.
- Q8 agent names: spec default. Names come from every `tool_use` in the file. A null or missing parent gives `orchestrator`, and an unknown parent gives `agent`.
- Q9 missing log: spec default. A missing file gives `{"next":0,"lines":[]}`, and `after<0` gives 422. Builder extension: any OSError (a directory, a permission error) also gives the empty page.
- Q10 Retry: spec default. It is the existing `POST /api/tasks/{id}/run`. Only tests were added.
- Q11 factory task: spec default. Both `branch` and `worktree_path` are set. Anything else is standalone and gets `run_id` null.
- Q12 refused rework spawn: spec default for the JSON API. An active run → 409 before any write. Any other refusal comes after the decision and the rework move are committed, and they stay. Builder note: `refuse_if_running` and `decide_review` run in separate transactions, so a run that starts in that gap is refused after the write and the task waits as stalled · rework. Round 2: the form route answers that post-write case with 200 and a header swap (see "You decide" above).
- Q13 rework session: spec default. The same `/factory <id>` with a new `--session-id`, no `--resume`.
- Builder (round 2): the form's post-write refusal is a 200, not a 409, because htmx swaps only 2xx responses. Same item as "You decide" above.
