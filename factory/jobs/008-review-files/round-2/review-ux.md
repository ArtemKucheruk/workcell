- `src/claude_factories/app.py:957` (`HUNK`) — the round 2 bound `\d{1,18}` stops a hunk header with a 19+ digit number from matching, so in a file that already has a hunk it becomes a context row. Verified live on a temp server: a file with `@@ -1,2 +1,2 @@` followed by `@@ -9999999999999999999 +1 @@` renders the header as a `ctx` row with text `@ -9999999999999999999 +1 @@` (the leading `@` is cut and no `hunk` row is drawn), and every later line in that file gets wrong old/new numbers. Spec Q5 says any `@@ -a[,b] +c[,d] @@` line is a `hunk` row, and this input has that form. Only a header as the first line of a file gets skipped, so `test_huge_hunk_number` passes without catching this. Fix: match the hunk header unbounded (`@@ -(\d+)(?:,\d+)? \+(\d+)(?:,\d+)? @@`) so it always emits a `hunk` row with the whole line as text. Call `int()` only when both numbers have at most 18 digits. Otherwise set `old = new = None` and `in_hunk = False`, so no numbering follows. Add a test with a valid hunk before the huge one, checking that the `hunk` row is there and the next rows are not numbered.
