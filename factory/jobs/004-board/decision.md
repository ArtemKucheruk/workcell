## Open questions
- Q1 (chips per round vs. the wireframe's single row): one row for the latest round only, `r<n> sec✓ ux✓ ui· co✗`, each chip titled `<reviewer>: <PASS|CHANGES|pending>`. `+A −D` (U+2212) is the latest round's total. Done cards show `N round(s)` instead, and nothing when there are no rounds.
- Q2 (stage text): in_progress cards show the raw stage name. `human_review` → `waiting on you`, `escalated` → `⚠ NEEDS YOU — escalated`, null → nothing. Run state is left to 014.
- Q3 (colors): `.escalated` gets a red left border and red badge text via `light-dark(#cf222e, #f85149)`. `waiting on you` is bold with no color. No other hard-coded colors.
- Q4 (factory state wording): `Factory: none` / `Factory: uncommitted` / `Factory: ready ✓`. The Create factory button and commit hint are left to 011.
- Q5 (links to pages that don't exist yet): the Code and `/tasks/{id}` links are rendered and 404 until 016/010 land. The card link has `draggable="false"`.
- Q6 (Run next): `<button disabled title="Runs aren't available yet">`, no handler. 014 enables it.
- Q7 (poll mechanism): no new route. `#board` re-fetches the full page with `hx-select="#board"` and `hx-swap="outerHTML"`, `every 3s` with a filter that skips polls during a drag. Forms and `#board-error` sit outside `#board`. Builder detail: the after-drop refresh is an htmx `refresh` trigger, not `htmx.ajax`, so the script makes no request besides the PATCH (AC23). If a poll is already in flight, htmx drops the refresh and the next poll, up to 3 s later, catches up. The builder also added an `htmx:beforeSwap` guard that discards a poll response landing mid-drag.
- Q8 (drop position): the drop goes in the gap before the first card whose midpoint is below the pointer. The position is the midpoint of the neighbors, `first − 1`, `last + 1`, or `1.0` in an empty column. Dropping into the same gap sends nothing. Float precision runs out after about 50 drops at one spot, and there is no renumbering.
- Q9 (drag ↔ API): one inline script with listeners on `document` sends `fetch` PATCH with `X-Requested-By: fctl`. An error shows a string `detail` or `Move failed (<code>)`, set via `textContent` and cleared on the next success. The builder added `Move failed (server unreachable)` for network errors.
- Q10 (form route): a new HTML form route, `POST /projects/{id}/tasks`, uses `form_field()` and `create_task()`, returns 204 + `HX-Redirect`, and gets 403/404/422 from the existing middleware and validation. `form_field()` strips the description too.
- Q11 (empty states): Backlog says `No tasks. Add one with + New task, or run fctl task add "title" in the repo.` and other columns say `No tasks`. All four columns always render.
- Q12 (keyboard alternative to drag): none built. Cards and links are focusable, and chips have text titles. A keyboard move control (for example a per-card status `<select>`) is yours to decide.
- Q13 (`position` not in the API): the page route reads `position` with its own query, and the API shape is unchanged.
- Q14 (where path and move form go): the `<h1>` is unchanged, the toolbar sits next to it, and the path and move form are below the header, outside `#board`.
