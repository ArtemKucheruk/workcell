## Backend refactor: layered packages
Decided 2026-10-18: app.py (1,600 lines) and cli.py are split into layered packages before the frontend work, so new
backend code lands in the new tree. Every job here moves code without changing behavior. The existing tests pass
with only their imports and locations changed (tests/ mirrors the new tree), and every JSON, HTML, and `fctl` output
stays the same. 034–036 all edit app.py, so they run one at a time.
- [x] 034-backend-layout: new docs/MVP.md §4.7 Code layout with the tree and rules below; FACTORY.md conventions and the review-code checks point at §4.7 (.claude/agents/review-code.md and the review-code factory template, §7.3). Tree under `src/claude_factories/`: `server/` (`create_app`, lifespan, the §4.5 middleware, domain error → HTTP mapping that keeps the `{"detail": …}` shape, `deps.py` providers), `controllers/` (one `APIRouter` per resource, plus `pages/` for the Jinja routes until 026), `handlers/` (use cases as plain functions, one module per resource), `dto/` (pydantic request and response models per resource), `repositories/` (all SQL, one module per table group), `adapters/` (`git.py` and `claude.py`, each a `Protocol` plus its subprocess implementation with argument lists), `domain/` (Status, Stage, and Reviewer enums, the §5.2 stage → status map, `NotFound` / `Conflict` / `TooLarge` errors), `lib/` (pure parsers and renderers: patch split, diff rows, run log, markdown, slug), `db/` (connection, `schema.sql`), `config.py` (env and limits), `cli/`. Rules: controllers → handlers → repositories and adapters; domain/ and lib/ import none of them; only server/ and controllers/ import fastapi, so handlers raise domain errors; handlers get repositories and adapters through `Depends`, so tests can swap in fakes; one handler call is one transaction. This job builds server/, config.py, domain/, db/, adapters/, and the deps, and moves workspaces, projects, and Create factory into the layers. app.py keeps the routes not moved yet, as a router that server/ includes. A pytest reads every module's imports with `ast` and fails on a wrong direction, on fastapi outside server/ and controllers/, or on SQL outside repositories/ and db/, with app.py exempt until 036.
- [x] 035-backend-tasks-reviews: into the §4.7 layers: tasks (list, create, get, patch, moves, events, stage → status), rounds (submit, the patch split into lib/, round diff, the 5 MB limit), verdicts, comments, decisions, approve, request changes, and the context markdown; response models in dto/ for each.
- [x] 036-backend-runs-pages: runs into the §4.7 layers through the claude and git adapters (worktree, env stripping, auth check, spawn, finish, stop, startup cleanup, run log parsing into lib/); the Jinja page routes and the code page into `controllers/pages/`, with each page's data built by a handler, so 020's `/api/pages/*` only adds JSON controllers; app.py deleted and `fctl serve` pointing at `server`; the architecture test drops its app.py exemption.
- [x] 037-cli-package: cli.py becomes `cli/`: `main.py` (argparse and the `fctl` entry point), `client.py` (HTTP with `X-Requested-By`), `git.py` (main checkout, default branch, the §7.4 temp-index capture), `output.py` (summaries, errors to stderr, exit codes), and `commands/` with one module per group (projects, tasks, runs, submit, review, agent); still stdlib only, which the architecture test checks for cli/.
